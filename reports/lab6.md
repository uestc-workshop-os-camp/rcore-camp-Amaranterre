# 问答作业

1. 在我们的多线程实现中，当主线程 (即 0 号线程) 退出时，视为整个进程退出， 此时需要结束该进程管理的所有线程并回收其资源。 - 需要回收的资源有哪些？ - 其他线程的 TaskControlBlock 可能在哪些位置被引用，分别是否需要回收，为什么？
   - 需要回收的资源首先就是线程的内存空间，其中就包括线程的用户地址空间和内核地址空间。同时也要回收其在`TaskManager`,`Mutex`,`Sem`,`ConVar`中的`queue`中保存的`Arc`引用，否则`TaskControlBlock`不会被回收。
   - 在`TaskManager`,`Mutex`,`Sem`,`ConVar`中的`queue`中被引用，且需要被回收。否则`TaskControlBlock`不会被回收从而造成内存泄漏。

2. 对比以下两种 `Mutex.unlock` 的实现，二者有什么区别？这些区别可能会导致什么问题？
   - 对于Mutex1，如果程序在`mutex_inner.locked = false;`后， `if`前被调度，则有可能会唤醒正在等待的一个线程；当调度返回后，程序继续执行`if`，此时又会唤醒另一个正在等待的一个线程，因此这个锁就失败了。
